# 产线数字孪生（本地离线版）

纯 Go 标准库实现的本地产线数字孪生：从本地 JSON 配置构建产线模型，用
离散事件仿真按时间推进，推演出工位加工、在制品流转、设备故障与质检
返工，输出产能、在制品统计和每个制品的流转轨迹。

- 不接真实设备、消息队列或数据库；
- 仅依赖标准库（`encoding/json`、`math/rand`、`container/heap` 等）；
- 不需要联网，`go build` / `go test` 均可离线执行。

## 目录结构

- `configs/line.json`：示例产线配置。
- `internal/config`：配置格式、加载与构建期校验。
- `internal/sim`：确定性离散事件仿真器（事件堆、故障、返工、统计、轨迹）。
- `cmd/twin`：命令行入口。

## 配置格式

顶层字段：

| 字段 | 说明 |
| --- | --- |
| `name` | 情景名称 |
| `seed` | 随机种子；同配置同种子结果完全一致 |
| `max_time_ms` | 仿真总时长（毫秒，必须为正） |
| `feed` | 投料间隔区间 `{interval_min_ms, interval_max_ms}`，均匀分布，min 必须为正且 max ≥ min |
| `stations` | 工位序列，第一个是进料口，最后一个必须是唯一的出口（`is_sink: true`） |

工位字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 工位标识，全产线唯一、非空 |
| `buffer_capacity` | 入口缓冲容量（不含机台上的 1 件），非负 |
| `duration_min_ms` / `duration_max_ms` | 加工时长区间（毫秒，均匀分布），出口工位除外；min 为正且 max ≥ min |
| `fail_per_hour` | 设备故障率（次/有效加工小时），非负；为 0 表示不故障 |
| `repair_min_ms` / `repair_max_ms` | 维修时长区间（毫秒，均匀分布）；故障率 > 0 时必须为正且 max ≥ min |
| `check_quality` | 是否在加工结束做质检 |
| `quality_fail_rate` | 质检不合格概率，范围 [0,1] |
| `rework_to` | 返工回流工位 id，必须是**当前工位之前**的工位（禁止前向成环） |
| `rework_max` | 单个制品允许的返工次数上限，非负 |
| `is_sink` | 出口标记；出口不加工、不质检，缓冲无限 |

工序流转：工位数组顺序即主流转方向，`i -> i+1`，最终汇入出口。
返工是唯一允许的“回流边”，且只能指向更靠前的工位。

### 构建期校验（拒绝带病模型）

下列问题在 `Config.Validate()` / `sim.New` 阶段直接失败，错误用
`errors.Is` 可区分类别：空产线、重复/空 id、未知引用（`rework_to`
指向不存在的工位）、前向/自返环、非法容量、非法加工或维修时长、
概率/故障率越界、出口缺失或不在末位、质检缺回流配置、投料间隔
非法、`max_time_ms` 非正。

## 时间推进与同刻事件规则

- 时间单位为毫秒，事件存放在最小堆中，按 `(时间, 优先级, 工位索引, 入队序号)` 排序。
- 同刻事件固定优先级：**完工(0) → 故障(1) → 修复完成(2) → 投料(3)**。
  同一优先级再按工位索引从小到大，最后按入队序号，保证完全确定、可解释。
- 每个事件处理完后执行一次 `dispatch`：按工位索引升序反复消解
  “阻塞工件搬运”和“空闲机台上料”，直到状态不再变化（定点）。
- 机台一次只加工一件；下游/回流缓冲满时完工工件**滞留在机台上**
  （blocked），缓冲一空出立刻按上述顺序搬运，物料不会消失。
- 出口缓冲无限，保证系统总有一个排空方向，主流转无环 + 回流只指向
  上游，因此不会发生循环等待死锁。

随机性全部来自以 `seed` 播种的仿真器私有 `math/rand` 源；仿真器
实例间不共享任何状态，多情景可并发运行。

## 故障与返工策略

- **故障**：故障率按每毫秒 `fail_per_hour/3,600,000` 折算，首次故障
  的有效加工时间服从指数分布，仅在“正在加工”时计时；故障瞬间冻结
  工件账（记录剩余有效加工时间），维修期间不产出完工事件；维修结束
  后以剩余时长继续加工，并重新抽样下一次故障。计划故障事件若晚于
  工件完工则自动失效。
- **返工**：仅 `check_quality=true` 的工位在加工结束时抽一次质检
  结果（故障/恢复不重抽）。不合格且制品返工次数 `< rework_max` 时，
  返工次数加一，工件送入 `rework_to` 的入口缓冲重新加工；已达上限
  则在该工位**直接报废**（scrap），不再回流。

## 统计口径与物料守恒

- `fed`：真正进入产线的件数（投料口缓冲满时的空投料尝试不计）。
- `output`：进入出口的成品件数。
- `scrap`：超返工上限报废的件数。
- `wip`：仿真结束时仍在系统内的件数 = 各入口缓冲占用 + 机台上
  （加工中/故障滞留/阻塞滞留）的件数。
- 任意时刻恒等式：**投入 = 产出 + 报废 + 在制**。产出与报废在离开
  系统时各计一次且仅计一次，不存在重复计数。
- `Traces` 给出每个制品的完整轨迹：`feed → start → (fault/resume) →
  pass/rework → … → output/scrap`，同种子复跑逐事件一致。

## 本地验证

```bash
# 构建
go build ./...

# 运行一次示例情景
go run ./cmd/twin -config configs/line.json

# 打印每个制品的流转轨迹
go run ./cmd/twin -config configs/line.json -traces

# 全部单测（-v 可看到场景/用例与结果日志）
go test ./... -v -count=1

# 竞态检测 + 重复运行（并发多情景用例）
CGO_ENABLED=1 go test ./... -race -count=10
```

测试覆盖场景：确定性复现、物料守恒（多种子）、设备故障、质检返工
与超限报废、15 类非法配置的构建期拒绝、示例配置端到端、8 个情景
并发互不干扰。
